### Excellent as shipped (no finding)
- Native `<dialog>` with `showModal()`: focus trapped correctly on all tested viewports (`tabLeftDialog: 0` on d1360 and p390); native inert layer makes the full page unreachable by keyboard and AT while the dialog is open. No fix required.
- `aria-labelledby="ld-h"` correctly names the dialog from the form heading (the form is moved into the dialog on open, so the `#ld-h` element IS inside the dialog when open).
- `#pf-err` with `role="alert"`: error announcements fire immediately on submit failure without requiring the user to navigate to the error; confirmed for all error states (missing, bad phone, 502, timeout, offline).
- All 19 CTAs: `open: true`, `focusBack: true`, `y2 === y0` — page does not move on open or close; focus returns to the trigger on close for every CTA and close method (×, Esc, backdrop, back button).
- `prefers-reduced-motion:reduce` CSS rule is correctly authored (line 1188 of built output): disables dialog entrance animation, backdrop animation, checkmark draw animation, and the progress bar animation.
- All four required fields: 16 px computed font size on both p390 and d1360, which avoids iOS focus-zoom. All four have `autocomplete` tokens (`name`, `organization`, `address-level2`, `tel`), and all are visible without scrolling (`fits.*: true`) across all viewports.
- No-JS path (`noJs.ok: true`, `deepLink.ok: true`): with JavaScript disabled, CTAs still reach `#contact` via hash scroll; phone, WhatsApp, and mail links are visible (opacity 1).
- Fast-send hold: `fast.ok: true` on p390 — the 3 s hold works correctly, preventing the intake's silent-drop path for typical autofill users.
- `label` wrapping with `<span>` for all form fields: all eight fields have programmatic labels confirmed by `lead.fields[*].label` in facts — labels present and `shown: true`.
- Sent-state re-open: `replies.ok.reopenedSent: true` — a returning visitor who taps a CTA after sending sees the sent state, not a blank form. Lead count does not increment (`leadsAfter: 1`, same as `leads: 1`).
- The `<details>/<summary>` disclosure for "עוד פרטים (לא חובה)" uses native HTML semantics; browsers expose the expanded/collapsed state to AT without additional ARIA; fields inside are removed from tab order when closed.
- Touch target for `.ld-x`: `width:44px;height:44px` confirmed in CSS (line 1168 of built output) — meets 44 × 44 px minimum on all viewports.
- `aria-hidden="true"` on all decorative elements (`.ld-pic`, `.ld-grab`, `.ld-bar`, `.ghost`, step SVGs, partner logo images with `alt=""`).

### World-class upgrades (beyond defects — what would make this the best lead flow in its category)

1. **Announce success in a persistent `aria-live` region outside the dialog.** When the dialog closes after a successful send, drop a brief message into a persistent `role="status"` region in the page (outside the dialog, so it survives dialog closure): "הפרטים נשלחו בהצלחה." This reaches the screen reader even after the 2 s / 6 s close, and removes the timing dependency entirely. The dialog's own `#pf-done` message remains for sighted users; the live region is the AT announcement.
2. **Progress indicator for the 3 s send hold.** The button says "שולח…" and is disabled for at least 3 s before the request fires. Add a `role="status" aria-live="polite"` sibling that announces "שולח…" when the button is disabled, so screen readers know the form is processing rather than frozen. A sighted spinner or subtle animation inside the button would add visual parity.
3. **`autocomplete="name"` on phone field.** The phone field has `inputmode="tel"` and `autocomplete="tel"` — correct. The name field has `autocomplete="name"` and the business field `autocomplete="organization"`. Add `autocomplete="address-level2"` to city — already done. Verify that Shopify's CSP does not block autocomplete (some Shopify-hosted pages restrict this via header; test on device). Already implemented — this note is a verification reminder, not a gap.
4. **`lang="he"` on the dialog element** (or confirm it inherits from `<html lang="he">`). A dialog placed in the top layer in some browsers may not inherit the `lang` attribute for TTS language selection. Adding `lang="he"` directly to `<dialog id="ldlg">` in the shell ensures VoiceOver/TalkBack selects a Hebrew voice for the form content.
5. **Visible focus ring on all CTA links.** The existing `.btn:focus-visible` rule (line 1020–1022) provides a 3 px green outline on buttons. Check that the hero slide `.sub-cta` "רוצה מחירון" links (which use `.sub-cta:focus-visible`) show the ring against the hero image background. If the image darkens the green enough to reduce ring contrast below 3:1, add a white halo: `outline-offset:2px; box-shadow:0 0 0 4px white`.

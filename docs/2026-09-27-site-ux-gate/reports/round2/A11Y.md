### New steps: screen reader and keyboard walk (§9.4 evidence)

**On dialog open (ask step):**
SR announces "בואו נעבוד יחד, dialog" from `aria-labelledby="ld-h"` (the `<b id="ld-h">` inside `.pf-head`). Confirmed name across all viewports.

Focus lands on `p#pf-ask-q` (all viewports: `lead.open.focus: "p#pf-ask-q"`, `focusIn: true`). SR reads "יש לכם עסק? אנחנו עובדים רק עם עסקים, בסיטונאות." The question has `tabindex="-1"` — it receives programmatic focus only; `.pf-q:focus{outline:none}` suppresses the ring correctly for programmatic-only elements.

Keyboard Tab order in ask step: `.ld-x` → "כן, יש לי עסק" button → "לא, לשימוש פרטי" button. All other form content is `display:none`. Both ask buttons: `h: 52`, `shown: true` — touch target adequate.

**"לא, לשימוש פרטי" → private step:**
Focus: `p#pf-priv-q` (`steps.focusNo: "p#pf-priv-q"`, all viewports). SR reads "אנחנו עובדים רק עם עסקים. ללקוחות פרטיים, המוצרים שלנו נמכרים באתר של אליטה אופק." **"חזרה" → back to ask:**
`steps.stepBack: "ask"` — focus returns to `p#pf-ask-q`. Correct.

**"כן, יש לי עסק" → form step:**
Focus: `b#ld-h` on touch (`steps.focusYes: "b#ld-h"`, p390), `input#pf-name` on pointer:fine (`steps.focusYes: "input#pf-name"`, d1360, d1920). Form fields all have labels (`lead.fields` — all `shown: true`, all 16px, autocomplete tokens correct). `lead.fits.*: true` across all viewports — all required fields and send button fit without scrolling.

Second open after a "yes" answer: `steps.stepReopen: "form"` (form step, not ask step) — the business-confirmation persists for the visit. Correct.

**After send → pick step:**
Focus: `p#pf-pick-q` (`replies.ok.focusSent: "p#pf-pick-q"`, both viewports). SR reads "מה הכי מעניין אתכם? נשלח לכם את התפריט בוואטסאפ." (the `.pf-pick` has `role="group" aria-labelledby="pf-pick-q"` — correctly groups the five links under the question). `replies.ok.axe: []` — no violations in sent/pick state. `stayedOpen: true` — dialog does not auto-close. shot: `/tmp/claude-0/-home-user/69951ae0-cef0-56a2-ac9c-bac1353b3e2f/scratchpad/gate-r2/site-ipad/p390-lead-04-sent.png`

Five WhatsApp lines: `מאצ׳ה`, `אובה`, `צ׳אי מסאלה`, `תמציות תה`, `בניית תפריט משקאות בעסק שלי`. Each `<a>` element: `blank: true`, `h: 52`, meaningful Hebrew text as link label. `openWhileAway: true`, `closedOnReturn: true`. Dialog closes on `visibilitychange` when the visitor returns; focus returns to trigger (`focusBack: true`); page is where it was (`y2 === y0`). Correct.

**Product window (fmodal) → lead dialog:**
All three card CTAs (i=14, 15, 16): `fmodalFocus: "fm-name"` — title element takes focus on fmodal open. `fmodalAfter: false` — fmodal closes before lead dialog opens; focus cleanly transfers to the lead dialog's ask step.

**Dialog and modal names:**
- Lead dialog `<dialog id="ldlg" aria-labelledby="ld-h">`: name "בואו נעבוד יחד". Correct across all steps (the `b#ld-h` is always visible in `.pf-head`; in priv step the subtitle `.pf-head span` is hidden but the `<b>` remains).
- Product window `#fmodal`: per §9.2 fix "a named modal; its title takes focus." `fm-name` is the accessible name. Consistent with `fmodalFocus: "fm-name"`.

**Page contrast (lead.axePage):**
`p390` and `d1360`: `["color-contrast ×1", "frame-title ×2", "heading-order ×2", "region ×65"]`. Dialog itself: `lead.axe: []` across all states (open form, error, sent). One contrast failure persists on the page (outside the dialog); see A11Y-R2-01.

**Reduced motion:**
`lead.reducedMotion: "none"` — `prefers-reduced-motion:reduce` CSS rule is authored in the patch; animations are suppressed when the preference is set.
